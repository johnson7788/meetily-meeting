        1 # 会议聊天 Agent 实现计划
        2
        3 ## 目标
        4 将现有的简单 LLM 对话升级为 LangGraph Agent，支持用户自由提问（如"当前对话条数有几条"），Agent 可通过工具读取和搜索会议记录来回答
          问题。
        5
        6 ## 架构设计
        7
        8 ```
        9 用户输入 → Frontend ChatPanel → POST /api/meetings/{id}/chat → LangGraph Agent
       10                                                                     ├── read_meeting tool (读取会议完整记录/元信息)
       11                                                                     └── grep_meeting tool (关键词搜索会议内容)
       12 ```
       13
       14 ## 实现步骤
       15
       16 ### 1. 添加 langgraph 依赖
       17 - `backend/pyproject.toml` 添加 `langgraph>=0.4.0` 和 `langchain-openai>=0.3.0`
       18
       19 ### 2. 创建 Agent 模块 `backend/app/services/meeting_agent.py`
       20
       21 定义两个工具：
       22
       23 **read_meeting** - 读取会议信息
       24 - 输入参数：`section`（可选，值为 "transcripts" | "summary" | "action_items" | "meta" | "all"，默认 "all"）
       25 - 返回：对应部分的会议数据
       26 - `meta` 返回：标题、创建时间、转写条数、发言人列表等
       27 - `transcripts` 返回：完整转写文本（带序号、时间戳、发言人）
       28 - `summary` 返回：摘要内容
       29 - `action_items` 返回：待办事项列表
       30
       31 **grep_meeting** - 搜索会议内容
       32 - 输入参数：`keyword`（搜索关键词）、`speaker`（可选，按发言人过滤）
       33 - 返回：匹配的转写片段列表（带上下文）
       34
       35 Agent 逻辑：
       36 - 使用 LangGraph 的 `create_react_agent` 创建 ReAct agent
       37 - System prompt 指导 agent 使用工具回答问题
       38 - 会议数据通过闭包注入工具（不需要每次从 DB 查询）
       39
       40 ### 3. 修改后端 chat endpoint
       41 - `backend/app/services/meeting_service.py` 中的 `chat_with_meeting` 函数
       42 - 调用 LangGraph agent 替代直接 LLM 调用
       43 - 保持接口不变（request/response 模型不变）
       44
       45 ### 4. 修改前端 ChatPanel
       46 - `frontend/src/components/summary/ChatPanel.tsx` 的 `handleSend` 函数
       47 - 将 placeholder 响应替换为实际调用 `api.chatWithMeeting()`
       48 - 传入对话历史 history
       49 - 显示返回的 answer 和 citations
       50

       59
       60 ## 注意事项
       61 - Agent 的 LLM 配置复用现有的 `get_llm_provider/model/api_key`
       62 - 对于 Qwen provider，使用 langchain-openai 的 ChatOpenAI（兼容 DashScope）
       63 - 工具返回的内容不需要太长，避免 token 浪费（transcripts 超过一定长度时截断）
       64 - Citations 从 agent 的工具调用结果中提取（grep_meeting 返回的 segment_id）
